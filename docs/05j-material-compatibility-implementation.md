# 05-J · 혼합형 제작의 재료 선택 엔진 (첫 구현 단위)

> 작성: 2026-10-27. PR #130. 설계 기준: [자원 마스터 v0.5](./resource-master-v05.md), [제작 계약 v0.5](./resource-crafting-contract-v05.md).

## 이번 구현
- src/material-compatibility-05j.js: 정확한 definitionId 또는 재료군 family/form/minGrade/필수·금지 태그/허용 출처를 비교한다.
- 같은 재고가 정확 ID 슬롯과 범용 슬롯에 동시에 필요할 때 **정수 최대 유량**으로 전체 슬롯의 할당 가능성을 계산한다. 순차 탐욕 할당에 따른 잘못된 부족 판정을 피한다.
- 입출력은 직렬화 가능한 단순 객체. 원본 인벤토리는 변경하지 않는다. 모듈은 **재료 소비·아이템 생성·턴/세계 시간 소비·저장 쓰기·신 금기 판정을 하지 않는다**.
- 테스트 tests/05j-material-compatibility.test.mjs: 정확/범용 재료 충돌, 속성·출처 제한, 이중 사용 방지, 잘못된 입력, 복수 스택 합산.

## 통합 전 필수 단계
1. 슬롯의 범용 기준은 신뢰 가능한 ItemRegistry/정적 정의에서 읽고, 클라이언트의 임의 family/grade/출처 주장을 사용하지 않는다.
2. '부위 후보 539개'에 실제 itemDefinitionId, family, form, quality, origin/preservation 정책을 확정한다. 기존 식물·광물 획득 원장과 중복 생성하지 않는다.
3. 실제 제작 요청에서 원자적 consume→resolve→credit를 검증하고, 기존 05-H/I exact-ID 제작법을 변경 없이 병행 운영한다.
4. 신규 materialManifest를 저장해야 하는 시점에만 세이브 v3 이전 정책과 기존 슬롯 불변식을 별도로 승인한다.
5. 자동/수동 동일 결과, 잘못된 후보 선택, 재료 부족, 상이한 출처, 금기 예고, 다중 제작 실패의 통합 회귀 테스트를 추가한다.

## 주의
설계 마스터의 348개 잠정 원천, 384개 지역 배치, 539개 잠정 산출 부위, 56개 레시피 후보를 전부 런타임에서 채집·제작 가능하게 만든 것이 아니다. 이 PR은 순수 매칭 엔진 첫 번째 조각이다. 희귀도·공정 시간·가격·전승 공식은 여전히 시험/검토 대상이다.
