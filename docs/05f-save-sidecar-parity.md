# 05-F 저장 v3 ↔ 광상 읽기 전용 뷰 동등성 검증

- 실제 엔진에서 광산 이동, 광맥 발견, 채굴 후 `createSaveV2 → prepareSecondsV2ToV3 → createSaveV3 → decodeSaveV3 → applyApprovedSave` 순서로 저장·복원한다.
- 저장 원본 `mineralDeposits05E`가 바이트 수준(JSON 표현 기준)으로 동일하게 보존되는지 검사한다.
- 광상 그룹 `sidecar`는 저장 v3에 삽입하지 않는다. 로드한 권위 있는 재고에서 **재계산**하고 원래 스냅샷과 일치하는지 검증한다.
- 로드 후 추가 채굴 시 이전 스냅샷을 거부하고 감소한 매장량을 다시 계산한다.
- 잘못된(음수) 매장량을 가진 저장 파일을 자동 복구하지 않고 거부한다.

이번 단계는 실제 저장 스키마를 수정하지 않는다. 그룹 재고의 중복 소비 및 저장 데이터의 이중 원장 생성을 피하기 위한 안정성 테스트다. 실제 복수 광물 동시 산출은 별도 PR에서 설계한다.
