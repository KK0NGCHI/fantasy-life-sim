## 1. 목표 및 범위

**완료 사용자 경험:** 캐릭터를 생성해 마을에서 시작 → 실제 씨앗을 획득 → 거점에서 파종 → 게임 시간을 진행하고 관리 → 성장한 작물을 수확 → 수확물을 실제로 먹거나 요리 → 산림 자원을 채집/가공해 사용 가능한 도구·생산 시설 제작 → 상인에게 산출물 판매 → 돈으로 씨앗 또는 설비 재료 구매 → 생산 규모를 확장 → 저장·새로고침·로드 후 같은 생활 계속.

M1은 농업 UI 버튼만 만드는 작업, 상점 화면만 만드는 작업, 제작법을 몇 개 늘리는 작업이 아니다. 각 행동의 실제 상태 변화와 재고·시간·숙련·금전·저장을 하나의 흐름으로 만든다.

### 포함 범위
1. **기존 자원/제작 재사용·정합:** 이미 동작하는 05-A~05-N 획득·제작 경로를 사용. 제품의 실제 효용(음식/도구/시설/판매) 및 현재 UI와의 연결.
2. **농업:** 마을 거점의 기능적 밭, 파종/돌봄/수확, 일회 및 반복 수확, 과수·균류로 확장 가능한 모델, 계절 적합성, 수확 적기와 밭에서의 부패.
3. **요리·소비:** 실제 식용 재료만 허용하는 조리 정의, 원료 소모·완성품의 직전 재료 기록, 먹기와 허기 회복; 재료 성질·출처의 이후 확장 경로 보존.
4. **거점:** 좌표 건축 없는 기능식 시설(기본 농지, 창고/기존 인벤토리 연동, 요리 시설, 작업대/용광로 접근, 후속 시설 확장) 및 업그레이드 재료 소모.
5. **상점·재화:** 최소 한 명의 마을 상인, 실제 재고, 구매/판매, 무제한 판매 수용 자금, 수급 재생, 재투자 루프. 장기 상인 투자는 이후 확장 가능한 슬롯만 확보.
6. **숙련·로그·도감 최소 연결:** 실제 행동에만 XP, 품목 발견 기록, 명료한 결과 로그, 기본적인 경제/생산 UI.
7. **자동 행동 기초:** 이미 정한 공통 디스패처를 반복 호출하는 제한적 반복 관리/수확/제작. 수동과 동일한 비용·결과를 보장하고 안전 중단 규칙 사용.
8. **저장·검증:** 새로운 상태를 v3에 안전하게 저장/복원. 이전 저장 원본 보호. 엔진/Windows/Chromium/장기 시나리오 자동 검증.

### M1 밖
실전 전투·몬스터 사망·부활·조우(M2), 전체 12신의 축복과 개종·신앙 관계(M3), 목축·포획·양식·심해 콘텐츠(M4), 대규모 NPC 관계/연애·복잡한 국가 경제, 농지 좌표 배치·자동 배관/전기, 아이템 신선도, 모든 후보 종의 즉시 활성화, 수천 품목의 제작법 수작업 추가.

## 2. 훼손하면 안 되는 확정 계약

- 단일 전역 캐릭터 레벨 없음; 54 숙련/7 능력치 유지. 직업/배경은 시작 정체성이고 이후 다른 생활 활동 금지 클래스가 아님.
- **접수된 게임 내 행동 실패도 1턴**; 기술적으로 접수 불가능한 입력만 0턴. 세계 시간은 정수 초이며 턴과 별개. 한 행동에서 시간·재료·세계·경험치의 부분 커밋 금지.
- 허기·HP·MP 자동화 중단은 선택 조건. **확정되지 않은 자연 감소율을 만들어 넣지 않는다**. 음식 섭취로 허기 회복은 별도 실제 행동으로 검증.
- 수확한 식재료의 인벤토리 신선도/자동 부패 없음. 수확 적기를 놓친 **밭의 작물**만 과숙/부패 가능.
- 작물은 일회 수확/계절 내 반복 수확/과수·관목·덩굴·균류·야생 약초 재배가 확장 가능한 구조. M1 초기 활성화 품목이 전체 세계관 종수의 상한이 아님.
- 농지·상점·작업 설비는 기능형. 무게/인벤토리 무게 제한 도입 금지.
- 직전 제작에 **실제로 소비된** 재료 종류/수량만 완성품 상세에 보여줌. 금기 판정용 originClass/신성 출처는 별도 보존. 완전한 재료 이력·원료 시점·좌표 추적 불필요.
- 상인은 실제 재고를 가지되 **상인 자금 부족으로 플레이어 판매를 막지 않는다**.
- 16개 고정 광역 지역은 16개의 타일 맵이 아님. 본 단계 농지에 별도 타일 맵 만들지 않음.
- 신의 금기는 행동 금지와 같지 않음. **칼두르 외우주 출처 장비 제작 사전 거부**와 의도적 위반 후 반응 간 충돌 C-01은 현행 코드에서 확인됨. M1은 충돌을 숨기거나 세계관 확정으로 올리지 않고, 일반 제작 흐름을 완성하면서 M3의 사후 반응 설계를 방해하지 않는 확장점을 만든다. **아르벨 금기 사건은 확정(밭 과숙); 보상·제재량과 신 대사는 미정**이므로 이벤트 기록까지만 포함하고 임의 패널티 금지.
- 생산량/재생 기간/가격/XP/상인 재고 복구 주기는 시험값으로 외부 설정. 기본값은 테스트에서 일관되게 사용하되 확정 밸런스라 표기하지 않음.

## 3. 엔진 상태와 일관성 계약 (구현 형식은 현재 코드와 맞춰 결정)

- 신규 도메인 예: `farm`(plotId, ownerId, cropId, plantedAtSeconds, growth, harvestWindow, harvestsRemaining, nextYieldAt, spoiled), `home`(functional station levels/unlocks), `economy`(player currency ledger, merchants, stock/replenish anchor), `recipe`/food consumption, `discovery`.
- **실제 구현 시에는 v3 save의 기존 `world.runtime`/extensions 계약을 먼저 검토**하고, 허용된 선택형 namespaced extension을 우선 검토. 현재 v3 디코더가 금지하는 필드를 임의 삽입하거나 구세이브에 신상태를 자동 합성해 원본을 덮지 말 것.
- 정의 ID와 상태 인스턴스 분리: seed/crop/food/material/item, plot, merchant, facility, recipe. ID는 안정적이며 기존 05-* ID를 임의 변경하지 않음.
- 정적 콘텐츠 승인: `candidate → approved → discoverable → obtainable → useful → ui-tested → save-tested`. 기존 348/539 후보 자료를 자동 활성화하지 않음.
- 행동의 모든 상태 변화는 **공통 디스패처 경로**로 처리. UI는 command를 제출하고 events/nextState만 렌더. 새 UI 전용 금전·소지품·턴 독립 원장 금지.
- 재화는 음수 불가, 구매 시 재화 감소=가격×수량, 상점 재고 감소/플레이어 재고 증가 원자적. 판매는 역방향이고 상인 보유 자금 한도로 차단하지 않음. 동시 명령/중복 요청 ID로 중복 지급 금지.
- 작물은 동일한 세계 시각에 중복 성장·회복·수확되지 않음. 동일 상태와 경과 초의 일괄/분할 계산 결과 동등. 계절 변경/시각 점프/장기 저장복원 시 일관성.
- 수확 가능 시기 이후 과숙 판정은 필드 상태에만 발생. 수확 완료된 재고에 작물 타이머 부착 금지.
- 음식 섭취는 소유한 식용 개체를 1회 소모하고 실제 허기만 증가(상한 준수), 이벤트와 시간/턴 1회. 회복량을 임의 영구 성장 규칙으로 확대하지 않음.
- 제작 소비·완성품 조성은 기존 material allocator / workshop / save v3 규칙과 일치. UI preflight와 실제 dispatch의 결과가 모순되지 않음.

## 5. 초기 활성화 콘텐츠 — 구현 제안 (최종 정식 명단/상한 아님)

**M1 최소 폭**을 작물 종류 자체의 빈약함으로 착각하지 않는다. 먼저 대표적인 생장·수확·가공·경제 메커니즘을 모두 통과시킬 실물 종을 활성화하고, 확장 가능한 정적 정의형 카탈로그로 구성한다.

- 밭 일회 수확: 밀·감자(기획상 명시된 실제 작물명, 시험용 생산량 적용).
- 반복 수확: 딸기·블루베리(계절 내 반복 생산 검증).
- 과수: 사과나무(밭작물과 구분되는 장기 수명/계절 결실; 거점 기능형 슬롯에서 테스트).
- 기초 음식: 생식 가능한 수확물, 밀을 이용한 기본 조리품 1개, 감자 요리 1개. 확정되지 않은 세부 레시피·효과는 시험안으로 명시.
- 기존 숲/광산 자원 및 가공품: 현재 활성 05-A~N 재료·도구 중 실제 회귀 가능한 항목만 연결.
- 상인: 마을 기본 생활 상인 1명(씨앗/필수 생산 자재의 실제 재고, 판매 대상 물품).
- 거점: 초기 농지와 기본 보관/작업, 추가 농지 1단계, 요리대 기능, 기존 공용 작업대/용광로.
- 신앙: 아르벨 밭 과숙 사건 기록만. 신별 축복·금기 수치·선호 행동 구현은 M3.

위 항목은 **구현 의사결정용 최소 후보**이다. 승인된 작물 정식 데이터가 없으면 ID·번역 표기·계절·성장일 등은 후보로 표시하고 실제 콘텐츠 승인 목록과 분리. 임의의 창작 작물명/신의 말투를 추가하지 않는다.

## 6. 실제 개발 순서 — 내부 작업이지 새 마일스톤 아님

1. **현행 기반 계측·최소 회귀 고정:** 활성 엔트리, v3 디코더, item world, 실제 제작/자원 UI, 테스트/빌드, 구세이브 백업. 로드맵·C-01 확인. 테스트로 현재 상태를 보존.
2. **상태/액션 단일 경로:** farm/home/economy/food 데이터 계약, 필드 검증, 명령과 오류, 시간·소유권·원자성, 버전 호환 준비.
3. **농업 종단간 구현:** 종자 획득·밭·파종·시간 경과·성장·수확·과숙·재생, 숙련 이벤트/UI·세이브.
4. **요리·거점 종단간:** 기존 제작 경로 재사용, 음식 소비와 효용, 기능형 설비 설치/확장.
5. **상거래 종단간:** 마을 상인 구매·판매·재고 및 가격·재입고, 아이템/골드·시간/XP·UI·저장 동등화.
6. **통합 회귀 및 브라우저 인수:** 처음부터 끝까지 사용자 명령으로 실행, 저장/새로고침, 장기 세계시간/계절, 데이터 손상/중복, Windows 자동/Chromium, 수동 QA 체크리스트.
7. 구현 중 발견된 소규모 결함은 즉시 수정하고 같은 M1 범위의 PR에 기록. 새 `M1-A` 등 관리 마일스톤을 만들지 않음.

**M1 중간 보고는 3회 이하 원칙:** 기반+농업 종단간, 요리/거점/경제 종단간, 최종 브라우저 인수. 심각한 결함 또는 사용자 세계관 결정 필요 때만 별도 보고. Git PR 개수와 사용자 보고 횟수는 별개.

## 7. 고정 인수 시나리오 및 반드시 통과할 반례

### E2E-01 시작·농업
새 게임·현재 상태 표시 → 마을에서 씨앗 구매 → 농지에 파종 → 게임 시간 경과 → 수확 → 실제 재고 증가와 농업 XP·작물 상태 변화. 수확 전/후 F5·로드 이후 동등; 부패는 밭에만 발생.

### E2E-02 반복·계절·과수
딸기/블루베리 등 반복 수확의 연속 수확과 계절 종료, 사과나무의 장기 결실. 같은 시각 재계산/장기 점프/분할 경과 동등, 무한 재수확 차단.

### E2E-03 소비·조리
수확 재료로 요리 → 정확 재료 소비 → 완성품의 직전 재료만 기록 → 음식 섭취 → 허기 실제 변화. 재고 부족/비식용 원료/존재하지 않는 제작법/다른 소유자 재고는 거부하고 원자성 유지.

### E2E-04 산림 제작·거점
숲에서 실제 목재 수확 → 기존 가공법으로 판재/도구 제작 → 필요한 거점 시설을 설치/확장 → 설치 전·후 기능 차이가 재현됨. 제작 소재와 재고 보존, 출처 메타 유지.

### E2E-05 교역·재투자
상인에게 작물/가공품 판매 → 플레이어 골드 증가/물품 차감 → 씨앗/자재 구매 → 재파종 또는 시설 증설 → 지속 가능한 생산 사이클. 재고/골드 음수, 무한 복제, 상인 자금 부족 매도 거절 금지.

### E2E-06 저장·복구·구버전
전체 시나리오 중간 저장 → 페이지 리로드 → 위치/시간/농지/수확/재고/돈/시설/상점/발견 상태 동등. v3 구슬롯 원본 불변. 손상 파일·새 버전 파일은 기존 정상 진행을 훼손하지 않고 거절.

### E2E-07 자동/수동 동등
같은 시드·초기 상태·동일 명령 목록에서 수동과 반복 제어의 턴/경과 시간/생산량/XP/RNG 동일. 안전 중단과 취소 후 추가 행동·저장 가능.

### 반례 게이트
중복 명령/중복 이벤트, 유효하지 않은 actor/owner, 외부 소유 스택, 성장 전 수확, 존재하지 않는 씨앗, 틀린 계절, 수확 마감 지난 밭, 작업대 미접근, 잘못된 UI preflight, 음수 또는 NaN 가격·수량·시간, 저장 변조, 다중 탭 충돌, 오래된 아이템 정의 참조, 기초 생산 재고가 소진된 상태에서 재투자 경로 막힘.

## 8. 자동 테스트·수동 검수·완료 정의

- CI: `npm run check`; 기존 Node tests 및 세이브·원장 보존 검사; Linux 엔진·Windows smoke·headless Chromium. UI E2E는 마을→농지→요리→상점→저장까지 **실제 브라우저 조작**을 검사한다.
- 장기 테스트: 최소 28/112/224일 게임 시간 시험, 계절 경계, 재생/과숙 멱등성, 생산-판매-재투자의 재화/아이템 보존. 숫자는 승인된 밸런스 아님.
- 사용자의 Windows Chrome/Edge 실제 수동 검수는 자동 CI와 별도 표시. 기능·기술 인수와 UX 수동 인수를 혼동하지 않는다.
- 완료 판정: E2E-01~07 전부 자동 검증 + 브라우저 상호작용 성공 + 데이터/저장 회귀 통과 + 사용자 수동 인수 확인(별도). 일부 통과만으로 M1 완료 선언 금지.
- **M1 범위 변경 조건:** 위 시나리오 수행에 필요하지 않은 신규 콘텐츠/세부 현실성은 후속 목표로 이동. 설계 변경은 확정 세계관·저장 비호환·보안·실제 진행 봉쇄 문제인 경우만 명시적으로 처리.

## 9. GitHub 운영 및 보고

- M0 PR #157이 현재 main에 미병합이면, M1 **문서 PR**은 M0 문서 브랜치 기반으로 작성. M1 **구현 PR**은 M0 병합 후 최신 main에 분기한다. 병합되지 않은 문서 브랜치 기반으로 게임 코드를 무작정 연쇄 적층하지 않음.
- 개발자는 기능군별 작은 PR을 작성할 수 있으나 상위 완료 기준은 단일 M1. 별도 요청 전 main 병합/강제 푸시/기존 저장 슬롯 파괴 금지.
- 작업 보고 형식: `M1 진행률(인수 E2E 통과 N/7), 플레이 가능 루프, 테스트 근거, 결함/불확실성, PR 링크, 다음 필수 연결`. 임의의 퍼센트 완성도 금지.
- 최종 보고 시 **구현한 것과 미구현한 것**을 분리하며, 최초 설계 예시를 사용자 확정 세계관으로 포장하지 않는다.
