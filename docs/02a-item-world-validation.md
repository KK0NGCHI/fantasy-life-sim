# 02-A 후속 — 아이템 배치·보관 관계 검증

02-A의 정의·인스턴스 레지스트리에 연결 가능한 **독립 아이템 세계 스냅샷** 검증을 추가한다. 기존 `GameState`/UI/저장 구조를 교체하지 않는다.

- `ItemWorldSnapshot`: `items`, `placements`, `containers`를 ID로 상호 참조하는 JSON-친화적 구조.
- 위치: 인벤토리, 장비 슬롯, 컨테이너, 세계 중 한 곳. 중복/누락 배치·없는 아이템 ID를 거부.
- 용기: 양방향 참조 일치, 내용물 중복 및 순환 보관 관계를 거부. 용기 자격, 용량, 무게·슬롯 제한은 미정이므로 검사하지 않는다.
- `prepareInventoryMigration`: 기존 `state.inventory.items`의 기본 필드만 후보 인스턴스로 복사한 후 레지스트리 검증. **상태를 교체하거나 실제 세이브를 마이그레이션하지 않음**.
- 모든 기존 테스트를 유지하며 `npm run check`로 검증.
- 다음 단계: 콘텐츠에 실제 컨테이너·장비 정책을 확정하고 런타임 저장 스키마와 연결. 유효하지 않은 세이브는 변경 전 상태를 유지하도록 저장 단계에서 보장.

**주의:** 레지스트리의 반환 Map과 Set은 JS 런타임에서 완전한 불변 객체가 아니다. 등록 후 외부 변형을 금지하는 캡슐화는 실제 로더에서 보강해야 한다.
