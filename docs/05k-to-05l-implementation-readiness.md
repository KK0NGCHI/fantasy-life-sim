# 05-K 제작 통합 결과와 05-L 자원 콘텐츠 활성화 진입 기준

> 2026-10-27. 사용자 승인된 자원 설계 v0.5를 따르는 구현 단계 문서. 신규 생물종이나 539개 부위를 일괄 게임에 노출하는 승인이 아니다.

## 05-K 구현 범위
- 기존 05-H/I 정확 ID 제작 레시피를 05-J 재료 할당기 및 05-K 원자적 inventory consume/credit 함수에 연결.
- 실제 소유 인벤토리만 소비하며, 부족·잘못된 계획·충돌은 상태 변경 없이 반환.
- 신규 범용 슬롯은 caller가 trusted 정적 itemDefinition으로 family/form/grade/traits/origin을 채운 경우에만 후보로 사용한다. 외부 명령에서 임의의 메타데이터를 보내서는 안 된다.
- 구형 recipeId·주괴/도구 outputId, 수량, 제작 시간, 제작 장소, save 스키마는 유지한다.
- 생산물에 materialManifest가 **아직 저장되지 않는다**. 순수 배분 함수가 내놓는 allocations는 후속 저장 설계의 입력이 될 수 있다.

## 05-L 초기 활성화 후보
| 우선순위 | 자원 원천 | 게임 내 기존 획득 경로 | 가공·제작 연결 | 설계/구현 차이 |
|---|---|---|---|---|
| 1 | 참나무 통나무 | 05-A 벌목 | 05-H 참나무 판재 → 05-I 목재 낚싯대 | 현행 exact ID 루프 유지, 수종별 확장 가능 |
| 2 | 들풀 | 05-A 채집 | 현행 낚싯대 보조 재료 | 실제 fiber family/type 승인 전 범용 장갑·밧줄 미활성 |
| 3 | 목이버섯 | 05-B 균류 채집 | 05-I 채집 장갑 | 현행 exact ID 유지, 식용 안전은 별도 |

| 5 | 점토·암석 | 05-A 채광/자원 풀 | 05-H 벽돌·다듬은 석재 | 건축 소비처는 아직 미구현 |

## 05-L 개발 준비 계약
1. **후보 명세를 구현 확정으로 전환:** 마스터 row의 정식 sourceId/itemDefinitionId를 기존 카탈로그에 대조, 새로운 원천은 이름·서식·재생·도구·부위·획득·사용처 승인.
2. **material metadata 레지스트리:** family, form, grade, traits, originClass를 itemDefinition에서 해석하고, 05-J 함수에 직접 trusted metadata로 전달. 기존 인벤토리 인스턴스의 quantity/id를 소유권 검사와 연결.
3. **실제 신규 레시피:** 처음에는 wood.plank / fiber.rope / storage.basket 중 획득 재료의 실경로가 검증된 단일 체인으로 배포. 결과물 itemDefinition과 생산 시설/시간/반복 자동작업 처리.
4. **원자성과 보존:** 부족·중복 슬롯·타 소유자·장시간 자동 반복/재저장·동일 턴 요청 테스트. 도감 등록/드롭/실소비 경로를 end-to-end 확인.
5. **인스턴스 속성 manifest:** 혼합 재료 장비에 실제 출처를 남기려면 v3 save 계약, 이전/검증, 스택 정체성과 기원별 금기 판정까지 사전 설계 및 테스트.
6. **금기 사전 안내:** 신성 나무/수생 보호 생물/이질 기원 장비 제작 경고. 05-K 판정기 자체가 종교 행위로 오판하지 않음.
7. **회귀:** 05-H/I의 수량/시간/원장/저장 동작을 그대로 유지, Windows·Chromium·엔진 CI + 실제 브라우저 수동 검수.
