# 02-B IndexedDB 실브라우저 안정성 검증

## 목적
기존 Node 단위 테스트 34개는 DB 트랜잭션 자체를 실행하지 않는다. 이 파일의 HTML은 브라우저의 **실제 IndexedDB**를 사용해 저장/재열기/충돌/손상 시 복구 후보 확인을 수행한다.

## Mac 실행
```bash
git fetch origin
git switch test/02b-indexeddb-browser
npm run check
npm run build:engine
python3 -m http.server 8000
```
브라우저에서 `http://localhost:8000/tests/browser-02b.html`로 접속한 뒤 **검증 실행**을 클릭한다.

확인 대상: ① 최초 트랜잭션 저장 ② 새 DB 연결에서 턴/RNG/아이템 복원 ③ 오래된 revision 덮어쓰기 거부 ④ 이전 정상 스냅샷 보존 ⑤ 손상된 최신 저장 불러오기 실패 ⑥ 이전 유효 스냅샷 조회 ⑦ 승인 전 현재 상태 변경 금지. 마지막에는 테스트용 독립 DB를 삭제한다.

**중요:** 이 페이지는 기존 게임 저장소(`somnium-saves-v1`)를 열지 않는다. 생성 시 UUID가 들어간 임시 DB만 사용하므로 사용자 세이브에는 손대지 않는다.

## 분명히 구별할 사항
- GitHub CI: TypeScript·Node 테스트·기존 UI 구문 검증. 이 브라우저 테스트 HTML은 CI에서 직접 클릭·실행되지 않는다.
- 실제 Mac 브라우저에서 7개 검증을 실행해야 **실브라우저 확인 완료**라고 말할 수 있다.
- 이 테스트는 일반적인 비정상 종료, 디스크 전원 손실, Safari의 저장소 회수, 실제 UI 사용 흐름, JSON 업로드/다운로드까지 보장하지 않는다.
- 파일 복구는 이전 정상 항목을 **보여주는 단계**만 검증한다. 사용자가 승인하기 전에 최신 포인터를 자동 전환하지 않는다.
- 02-A 신규 아이템 모델의 소재/품질/희귀도/강화/배치 정보는 현행 `GameState.schemaVersion=1`이 지원하지 않으며, v1 저장 포맷이 이를 조용히 받아들이지 않도록 방어 검증을 추가했다. 스키마 v2와 데이터 전환은 별도 검토 후 진행.
- MDN: IndexedDB 트랜잭션 완료는 논리적 commit 완료를 나타내지만 갑작스러운 전원 손실까지 영구 저장을 확약하지 않는다.
