## 지금의 실행 순서
1. M0 문서/코드 경계 정리 및 PR. **기술적 검사 미실시는 인수 완료로 표현하지 않음.**
2. M1 한 개의 상위 목표로 진행. 내부 PR의 기준은 항상 최신 main. 프로덕션 기능은 `엔진 행동→상태/원장→XP·이벤트→UI→v3 세이브→E2E`로 종단간 구현.
3. 그 외 제안은 각 M단계의 backlog로 기록. 게임 규칙 변경, main 병합, 비가역적 세이브 변경은 별도 승인.

## M1 인수 시나리오 — 고정
새 게임→거점에서 씨앗 확보→파종→게임 시간 진행→수확→요리·제작→실제 소비 효과→상인 판매→종자 또는 시설 재투자→반복→저장/새로고침/복원. 추가로 숲 자원→목재 가공→도구 제작→실사용. 식품 인벤토리 자동 부패 없음. 밭 과숙 `crop.overripe` 발생. 경제·XP 시험 숫자는 최종 수치로 발표하지 않는다.

## 개발 보고 규격
`[M단계] 상태 | 실제 UI 동작 | 엔진·저장/테스트 증거 | 남은 필수 시나리오 | 결함·설정 충돌 | 브랜치/PR`.
'코드 구현', 'CI 통과', '브라우저 자동 확인', '사용자 수동 QA', '콘텐츠 승인'을 따로 표시. 사용자 Windows 브라우저 수동 인수 전 완료 선언 금지.
