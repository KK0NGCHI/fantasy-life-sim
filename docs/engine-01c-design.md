# 엔진 01-C — 세계 시계·난수·자동 진행 설계 결정

작성: 2026-10-22 · 상태: **기획 합의 / 코드 미구현**

참조: [01~02 기술 설계서](./engine-01-02-design.md), [01-B 구현 범위](./engine-01b.md)

## 1. 사용자와 합의한 게임 규칙

- **1행동 = 기본 1턴.** 실제 게임에서 접수한 실패 행동도 1턴 소비. 기술적 접수 오류는 0턴(01-B 계약 유지).
- **낚시·채광 등 오래 걸리는 작업은 여러 턴**을 소비할 수 있다. 소요 턴 수는 행동별 **최소~최대 범위**를 둔다.
- 관련 **숙련이 높아지면 해당 범위의 최솟값과 최댓값이 점차 낮아지는** 방향으로 설계한다.
- 구체적인 소요 턴 범위·숙련별 감소 폭·최솟값 하한·결과 분포 공식은 **미정**. 테스트와 별도 비교를 거쳐 정한다.
- 세계 시간은 **플레이어 행동 시에만 진행**, 메뉴·인벤토리·도감 열람 및 플레이어가 가만히 있는 동안은 멈춤.
- 일반적인 행동별 세계 시간은 **행동 종류에 따라 차등**, 후속 확장을 위해 상황별 보정 여지를 남김. 수치는 미정.
- 플레이어가 설정하는 자동 중단 HP·MP·허기 조건은 **퍼센트(비율)** 기준, 각 항목 선택적으로 켜고 끌 수 있음.
- 자동 진행 중 정보창을 열면 **일시 정지**. 창을 닫아도 저절로 재개하지 않고 별도 명시적 재개 입력으로만 이어감.
- 위험 지형은 **DCSS처럼 자동 경로 탐색에서 피함**. 사용자가 수동으로 움직이는 것과 자동 탐색은 경로 판단을 다르게 취급할 수 있음.
- 세계 생성용 난수 스트림과 일반 행동용 난수 스트림을 **분리**한다.
- 자동 진행은 수동 진행과 같은 행동 처리기를 호출하며 경험치·전리품 페널티가 없음.
- 타이머 지연·브라우저 비활성 상태를 게임 턴으로 소급 계산하지 않음.

## 2. 장시간 작업과 01-B의 1턴 계약

기존 01-B의 `DispatchResult.turnsSpent: 1` 계약을 직접 다중 턴으로 바꿔 버리면 실패 행동 처리 및 테스트의 의미가 훼손될 수 있다. **권장 설계(구현 전 기술 검토 대상):** 장시간 작업을 하나의 사용자 요청으로 시작하지만, 내부적으로 각 **작업 진행 틱을 일반 행동 1회(1턴)** 로 처리한다.

예시 개념: `fishing.start` 요청 → 소요 턴 범위 결정 → `fishing.tick`을 턴별로 처리 → 완료 이벤트. 이 이름은 개념 예시이며 실제 API와 도메인별 규칙은 후속 단계에서 확정한다.

이때 '작업 시작 자체가 1턴인지', 취소·중단 시 진행도가 보존되는지, 중단 뒤 이어서 수행할 수 있는지는 아직 결정하지 않았다. 구현 전에 **중복 턴 소비 없이** 시작/진행/완료를 구분하는 계약을 검증해야 한다. 작업 진행 중 위험·임계값 변화에 대응할 수 있도록 작업은 턴 경계에서 중단 가능해야 한다.

`turn`은 누적 행동 턴이며, `worldClock`은 별도 단위의 누적 시간. 1턴과 세계 시간은 일대일 대응이 아니다. 달력 길이와 세계 시간 단위는 별도 확정.

## 3. RNG 정책

- `worldGeneration`과 `gameplay`은 별도 시드/상태로 보존·복원. 어느 한쪽의 난수 소비가 다른 쪽 순서를 바꾸지 않도록 설계.
- 동일한 초기 상태·명령·각 스트림의 RNG 상태는 동일한 결과를 만들어야 한다.
- 세계 생성 과정에서 도메인별 추가 스트림이 필요한지는 이후 콘텐츠 규모를 보고 판단.
- PCG32는 우선 검토 후보. 구현체 정확성·브라우저/Node 재현성 테스트 후 채택 여부를 확정.
- 보안 토큰 생성 용도가 아님. 게임 랜덤성과 비밀번호학적 난수는 구별.
- 미접수/오류 명령은 게임 상태와 RNG를 모두 변경하지 않도록 설계.

## 4. 자동 진행 정책

컨트롤러 상태의 예시: `idle | running | paused | completed | stopped`. 타입 이름은 미확정.

1. 다음 행동 전 플레이어 상태, 사용자 중지, 위험 지형·적·사건, 경로 제외 구역을 검사한다.
2. 안전한 다음 행동을 선택한다. 위험 지형은 경로 후보에서 제외한다.
3. 01-B의 공통 `ActionDispatcher`에 명령을 전달한다.
4. 행동 결과/턴/세계 시간/난수 상태/이벤트를 반영한다.
5. 이후 다시 중단 조건을 검사한다. 정보창 열람은 `paused`로 전환한다.
6. 위험 발견·행동 불능·경로 부재·명시적 취소 시 중지하거나 완료하고 이유를 반환한다.

중단 임계값은 퍼센트 기반이며 0~100 범위 검증. HP·MP는 현재/최대값의 비율로 처리할 수 있으나, **허기 방향성(높을수록 배고픈지, 포만인지)** 및 최대값이 0인 경우의 정책은 아직 확정하지 않는다. 사용자에게 실제 표시하는 의미와 중단 비교의 방향을 정의한 뒤 테스트한다.

DCSS의 위험 회피는 **참고 원칙**이지 해당 원작의 지형 목록·경로 가중치를 그대로 가져온다는 의미가 아니다. 우리 게임의 위험 플래그와 도달 가능성 판단을 별도 콘텐츠 데이터로 정의한다.

게임 결과 처리와 UI 애니메이션 딜레이는 독립적이다. UI 업데이트가 늦거나 탭이 백그라운드로 가도 보상 턴을 실행하지 않는다.

## 5. 확정 전 보류 수치·규칙

- 장시간 작업 기본 최소/최대 턴 범위
- 숙련 상승에 따른 최솟값/최댓값 감소 함수 및 하한
- 숙련을 언제 계산하는지(시작 시 고정 여부), 턴 길이 난수의 분포
- 작업 중단 시 소모품·진행도 처리, 시작 턴 소비
- 행동별 세계 시간 비용, 세계 시계의 정수 단위, 4계절 달력 길이
- PCG 구현 버전과 씨드 인코딩
- 위험 지형 상세 분류/회피 실패 시 메시지, 지형별 수동 진입 정책
- 허기의 비율과 중단 비교 방향, 최대 HP/MP가 0인 상황의 처리

## 6. 구현·테스트 순서

- **01-C1 시계·다중 턴 작업 계약:** 01-B의 원자적 단일 턴 처리와 호환. 1턴 행동 및 긴 작업의 턴 정확성 테스트.
- **01-C2 RNG:** 독립 스트림 2개, 재현/상태 복원/실패 명령 불변 테스트.
- **01-C3 자동 컨트롤러:** 수동 동일 명령 처리, 위험 지형 제외, 퍼센트 임계값, 정보창 pause 및 명시적 resume, 수동 취소.
- **01-C4 통합:** 행동/턴/세계 시간/RNG/중단·재개 상태의 연속 실행 검증.

이 문서는 **합의한 기획 명세**이며, 01-C 엔진 구현 및 기존 UI 연결이 완료됐음을 뜻하지 않는다.
