# 02-C — v2 행동 엔진·저장 세션·실행형 화면

기준: 2026-10-22 · Draft PR #12

## 확정된 요구사항
- **무게 없음:** 아이템 무게, 총 적재량, 과적/이동 페널티, 상자 무게 제한을 엔진과 새 UI에 도입하지 않는다.
- 줍기: 세계에 존재하는 아이템을 인벤토리로 이동.
- 버리기: 선택한 여러 아이템과 부분 수량을 **영구 소멸**, 지면 배치 없음. 모달에서 직접 승인 전에는 0턴·무변경.
- v1 저장을 절대 조용히 변환/덮어쓰지 않는다. v1 백업 파일은 승인한 경우에만 v2 상태로 불러올 수 있으며, 원본 v1 DB를 변경하지 않는다.

## 구현
1. `V2ActionDispatcher`: v2 행동을 하나의 진입점으로 모은다. 기존 아이템 행동, 줍기, 확인된 일괄 버리기, 주입받은 일반 행동 핸들러. 1회 커밋에서 턴과 세계 시간을 한 번만 적용하며, 잘못된 명령·처리 오류는 0턴. 자동 진행도 이 진입점에 액션을 보내도록 후속 연결 가능.
2. `V2SaveSession`: 후보 저장을 검증하고 사용자가 승인한 경우에만 상태를 교체. IndexedDB v2 저장. `prepareV2Load`는 v1 봉투와 v2 봉투를 구별하며, v1에서 알려지지 않은 아이템 정의는 거부.
3. `v2.html`: 실동작하는 **독립 실행형 v2 화면**. 아이템 보기/소모/줍기, 일괄 버리기 확인 모달, 턴·세계 시간, 휴식, IndexedDB 저장/불러오기, JSON 백업 내려받기·업로드, 명시적 불러오기 승인. 개별 세이브 슬롯과 콘텐츠 팩은 현재 테스트용 예시.
4. `tests/engine-02c.test.mjs`: v2 행동·턴·세계 시간·실패 시 원상태 보존·v1 마이그레이션 승인.
5. 기존 `index.html` / `src/v3.js`는 아직 UI 시제품으로 보존. **기존 메인 UI를 v2 엔진으로 전부 이전한 단계가 아니다.** 새 `v2.html`은 실제 엔진 연동 검증용 별도 진입점이다.

## 실행·수동 검증
```bash
git fetch origin
git switch feat/engine-02c-v2-runtime
npm run check
python3 -m http.server 8000
```
- `http://localhost:8000/v2.html` 열기
- 사용/줍기/휴식: 턴과 세계 시간, 아이템 수량 변화를 검사
- 일괄 버리기: 취소하면 변화 없음, 승인하면 두 종류 이상을 1턴에 삭제
- 저장 후 재열기 → 불러오기 승인 → 이전 상태 복구
- JSON 내보내기 → 다른 브라우저에서 가져오기 승인
- 잘못된 정의 ID를 가진 v1 JSON은 거부하고, 유효한 v1 JSON은 명시적 승인 후 v2로 전환

## 남은 일
- 이 브라우저 UI는 독립 실행형이므로 메인 UI 시제품 화면과 데이터 흐름 통합이 아직 필요.
- 실제 콘텐츠 레지스트리 완성, 다중 수동 슬롯/퀵세이브/자동 저장 UI 및 설정, 저장 복구 후보 목록 UX, 실제 브라우저 연동 수동 실행 확인.
- 기존 01-C 자동 진행과 v2 통합 자동 행동 정식 접합, RNG timing 정책 일원화(일반 핸들러가 RNG를 갱신해도 덮어쓰지 않아야 함).
- 현재는 JSON 백업에 MAC/암호학적 무결성 검증이 없고 콘텐츠 버전 변환표도 없으므로 외부 임의 JSON은 검증 후에만 수락한다.

레퍼런스: [MDN IndexedDB 트랜잭션](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB), [MDN dialog 모달](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog). 브라우저의 `showModal()` 확인·취소 흐름을 따르고, 저장 트랜잭션의 `complete` 이벤트를 기준으로 성공을 보고한다. 그러나 물리적인 기록 영속성까지 보장하지 않는다.

## 정식 v2 진입점

새 코드의 기본 임포트는 `src/engine/v2.ts` (빌드 후 `dist/engine/v2.js`)이다. `ENGINE_STAGE_V2='02-C'`, `ACTIVE_GAME_STATE_SCHEMA_VERSION=2`를 명시한다. 기존 `index.ts`에 남아 있는 v1 stage/schema 상수는 과거 테스트 및 명시적 마이그레이션 호환을 위해 유지한다. 새 게임의 저장 스키마는 항상 v2.
