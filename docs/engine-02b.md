# 02-B — 안전 저장 시스템 (2026-10-22)

## 사용자 확정 사항
- 수동 세이브 슬롯 수 제한 없음 (브라우저 실제 저장 공간 제한은 존재).
- 자동 저장은 **완료된 행동 수 + 주요 이벤트** 기준을 병행한다. 간격과 이벤트 종류는 정책 주입으로 설정한다.
- 최신 세이브 손상 시 이전 정상 세이브를 **자동 적용하지 않고**, 복구 후보를 보여 사용자 승인을 받은 후 불러온다.
- 세이브스커밍 허용, 외부 JSON 백업 지원, UI 사용자 설정 별도 보관.

## 이번 구현
- `save/save-format.ts`: `somnium-save` v1 저장 봉투, 독립 contentVersion / state.schemaVersion, 현재 상태 기본 검증, JSON import/export, 손상·미지원 버전 거부, 상태의 비파괴 load 준비.
- `save/indexeddb.ts`: 브라우저 전용 IndexedDB 스냅샷 저장소. 변경 불가 스냅샷 기록과 슬롯의 최신 참조 변경을 단일 readwrite 트랜잭션으로 원자화. 슬롯별 revision 비교로 오래된 탭의 저장 거부. `listRevisions`는 유효한 복구 후보를 조회하지만 복구를 수행하지 않음.
- `save/autosave.ts`: 사용자 설정 행동 수·이벤트 목록에 의한 자동 저장 조건.
- 기존 `GameState.schemaVersion=1`의 아이템은 아직 구형 단순 인스턴스. 02-A의 상세 인스턴스/배치 데이터를 조용히 변환하지 않음; 이를 저장하려면 명시적 schemaVersion 개정이 필요.

## 제한 및 후속 작업
- 브라우저 UI 저장 메뉴, JSON 파일 선택/다운로드 UX, 사용자 승인 복구 UI는 **아직 연동하지 않음**.
- IndexedDB 실브라우저 통합 시험은 후속 UI 연동에서 필수. Node에서는 저장 포맷과 정책만 자동 시험하며 브라우저 트랜잭션 동작은 별도 검증 필요.
- 현행 기초 구조 검증은 정식 전체 JSON Schema / 모드·콘텐츠 버전 마이그레이션을 대신하지 않음. 변환 경로가 없는 미래 버전은 거부.
- 상태 검증 시 게임 규칙에 따른 HP 범위, RNG 알고리즘 내부 상태 유효성, 데이터 참조 무결성은 모두 추가 보강 대상.
- `saveVersion`은 저장 봉투 버전이며 `state.schemaVersion`과 구분. 정식 아이템 상태 도입 이전에 v2 계약을 별도 승인하고 마이그레이션해야 함.
- 브라우저 저장소는 포트/출처별로 별도. 외부 파일 백업은 기기 이전 및 보관을 위한 필수 UI 기능.

## 검증
`npm run check`로 기존 테스트 + 저장 포맷/자동 저장 조건 테스트 수행.

참고: MDN IndexedDB 트랜잭션 완료 및 저장소 분리, Stardew Valley 이전 세이브 복구 관행, RimWorld 다중 수동 저장 관리.
