# 03-B — 초 단위 광역 여행 후속 구현 / 인수인계

상태: 2026-10-23 · PR #27 · `design/global-clock-seconds-v1` 기준

## 이번에 완료한 범위
- 모든 18개 주요 보이지 않는 교통로의 시험 비용을 **게임 내 초**로 정의한다. 거점~숲은 1,500초(25분), 거점~초원 900초(15분), 산맥~화산 28,800초(8시간) 등.
- 광역 경로 탐색/스킵/중간 인카운터 발생 시 사용한 seconds를 정수로 합산해 적용한다. 이동은 실제로 지나간 구간까지만 진행, 중복 롤/시간 부과 없음.
- `time-seconds.ts`에 86,400초 하루, 첫날 오전 8:00 시작, 양의 정수/0 검증, 한국어 시간 포맷을 구현.
- 메인 지도에서 기존 “세계 시간 N단위”를 제거하고 “이동 시간 N분/N시간”으로 표시. UI 상단 시계도 `clock.elapsedUnits`에서 파생한 시·분으로 표시.
- 새 게임의 `world.runtime.timeBasis='seconds-v1'`을 명시하여 이 시간 의미가 **초**인 데이터와 과거 추상 단위의 v2 스냅샷을 구분.
- 레거시 v2 세이브는 자동으로 초 단위로 환산/덮어쓰지 않는다. `timeBasis`가 없는 이전 저장에서 새 03-B 여행을 시작·재개·스킵하려 하면 거부한다.
- 기존 저장 slot, 아이템 구조, 인카운터 RNG 분리, 무게 미도입, 버리기 영구 삭제 규칙을 보존한다.

## 주의: 정식 v3 이전 필요
이번 PR의 게임 화면은 아직 `GameStateV2.clock.elapsedUnits` 스토리지를 사용한다. **신규 월드에만 timeBasis 표식을 붙여 초 단위로 사용**하는 호환 이행 단계이다. 설계서에서 권장한 명시적 `saveVersion:3` 및 `clock.elapsedSeconds` 스키마, 구형 v2→v3 복제/승인 마이그레이션은 **미구현**. 구형 세이브가 자동으로 초가 되지는 않으며, 마이그레이션 UI 없이 이를 완료했다고 선언하면 안 된다.

활동별 세계 시간(전투 3초/채집 120초 등)은 아직 정식 duration 정책에 연결되지 않았다. 현재 기존 수동 생활 행동의 1단위 폴백은 초 단위 신규 월드에서는 1초로 처리되는 임시 값이다. 이 부분은 세계 시계 통합 작업에서 교정 필요.

`03-A` 사이트 수명의 120/360/900 추상 비용도 아직 초 기준 영속 필드로 전환하지 않았다. 수명 버전 마이그레이션은 별도 작업이다.

브라우저 `http://localhost:8000/`:
1. 새로운 월드에서 세계 지도 → 숲: **25분** 표시, 이동 후 상단 시계 **08:25** (인카운터가 없고 다른 행동이 없는 경우).
2. 초원 15분, 산맥·화산처럼 먼 경로는 합산해서 시간·일 경계 올바른지 확인.
3. 랜덤 인카운터: 팝업까지 소요 시간만 확정되고 ‘확인 후 계속’ 시 남은 구간만 진행하는지 확인.
4. 여행 중 F5 → 새로고침 → F9 → 승인 후 남은 경로가 유지되는지 확인.
5. 과거 `timeBasis` 없는 JSON 저장의 시간값은 자동으로 초로 읽거나 변환하지 말 것.
6. Windows Chrome·Edge 각각에서 폰트, 이동 정보, 시계 분과 롤오버, 저장 승인 흐름 점검.
