# 02-D 최종 안정성 검수 — 구현 마무리

날짜: 2026-10-22. 02-D 엔진/메인 UI 기능 마무리용 Draft PR.

## 완료된 계약
- 고유 ID의 무제한 수동 저장, 퀵 저장, 행동 수 + 주요 이벤트 자동 저장.
- 원자적 IndexedDB snapshot+pointer 커밋과 revision 충돌 감지.
- JSON 파일 내보내기 및 검증 후 가져오기. v1/v2는 명시적인 변환만.
- 손상된 최신 세이브는 자동 적용/대체하지 않으며 정상 과거 revision을 사용자가 고르게 한다.
- 사용자 승인이 있어야 라이브 게임 상태를 교체한다.
- 메인 UI v2 상태에 저장되는 것: 아이템 및 위치, 플레이어 HP/MP/허기, 턴/세계 시간/RNG, 현재 지역과 던전 위치/진입, 제한된 사건 기록.
- 자동 저장 시 갱신된 로그가 포함되도록 `nextLog`에서 정식 체크포인트를 즉시 동기화한다. 자동 저장 작업은 별도 순차 큐로 실행한다.
- 자동 저장 정책은 기기별 설정으로 저장하며 읽기 오류/형식 오류는 기본값으로 안전하게 대체한다. 기존 저장 및 게임 상태와 분리한다.
- 자동 저장 실패 메시지는 저장 관리자에서 확인할 수 있다. 무게 시스템 없음.

## 실제 데이터 범위 경계
아직 실제 구현되지 않은 퀘스트·성장·도감 시뮬레이션 값은 완료된 저장 데이터라고 취급하지 않는다.
현재 목업 UI의 모든 값(테마, 지도 UI 탭, 패널 스크롤/높이 등)은 **게임 세이브 대상이 아니다.** 장치별 UI 설정으로 처리해야 한다.
여행했었던 모든 지역 자동 수집은 아직 게임 월드 계약으로 보강할 필요가 있다. 출시 단계의 전체 상태 저장 완료와 02-D 핵심 영속 서비스 완료를 혼동하지 않는다.

## Windows 10/11 PowerShell 최종 검증
```powershell
git fetch origin

```
`py`가 없다면 `python -m http.server 8000`을 실행한다. 브라우저에서 `http://localhost:8000/`을 연다.

### 확인 체크리스트
1. 새로운 수동 저장 두 개 생성, JSON 내보내기, 임의 백업 다시 가져와 사용자 승인 후 상태 복원.
2. 지역·던전 이동, 아이템 버리기, 생활 행동으로 상태 변경 후 F5 → 새로고침 → F9 → 승인. 턴·지역·좌표·아이템·로그 비교.
3. 저장 관리자에서 자동 저장 간격을 2로 설정하고 주요 이벤트 설정. **페이지 새로고침 후 설정값이 유지되는지 확인.**
4. 생활 행동 2회 후 자동 슬롯 선택 → 불러오기 → 로그 마지막 항목이 포함됐는지 확인. 이벤트 기반 자동 저장은 지역 이동 직후 확인.
5. 손상된 슬롯은 자동 복구/덮어쓰기를 하지 않고 정상 이전 기록만 선택 목록에 보이는지 확인.
6. Chrome 및 Edge 각각에서 위 저장, 취소, 승인 흐름 확인. 저장/복원 전 상태가 승인 없이 바뀌지 않아야 한다.

자동 검사 통과와 Windows 실브라우저 통과는 별도 판정한다. 수동 테스트 로그 없이는 실브라우저 성공을 기록하지 않는다.
