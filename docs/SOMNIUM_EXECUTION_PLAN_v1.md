## 목표
실제 사용자 플레이로 확인 가능한 완결된 활동 루프를 개발한다. 기능 하나/PR 하나를 독립 마일스톤으로 늘리지 않는다. 기획 후보와 실구현, 자동 테스트와 사용자 수동 인수를 구분한다.

## 구현 순서 및 계약
- 기존 TypeScript 엔진과 JS UI, v3 저장을 재사용하며, UI는 단일 공통 행동 경로를 통해 게임 규칙을 실행한다.
- 1 게임 내 시도=1턴(실패 포함), 기술적 접수 실패=0턴. 게임 시간은 턴과 별개.
- 아이템 정의와 실물 스택/인스턴스, 소유권, 재료 실제 소비 명세, RNG, 시간·XP·영속화의 원자성 유지.
- 인벤토리 식품 자동 부패 없음. 밭의 과숙은 가능. 신성/외우주 출처 태그를 속성과 혼동하지 않음.
- 기존 데이터·슬롯은 무단 이전 또는 덮어쓰기 금지. 게임 규칙 변경, main 병합, 비가역적 세이브 변경은 별도 승인.
- 설정 미정 항목은 확정하지 않고 시험값·교체 가능한 설정으로 구현.

## 진행·보고 규칙
한 번에 하나의 대형 M단계 목표. 내부 PR과 테스트 분할은 허용하지만, PR 병합을 단계 완료로 보고하지 않음. 완료 보고에는 실제 UI 흐름, 통합 테스트, 브라우저 E2E, 저장 왕복, 사용자 수동 검수 여부, 남은 결함을 각각 제시. M0 기술 검증에 사람의 Windows 브라우저 수동 검수를 혼동하지 않음.

## 상세 출처
