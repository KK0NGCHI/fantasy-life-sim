# Somnium 05-M 자원 원천 확대 상세 계획 v0.1

> 2026-10-27. **설계 초안 / 신규 자원 코드 미구현**. 상위 [05-M~05-Q 로드맵](./resource-foundation-roadmap-05m-05q.md) 참고. 05-M 범위는 숲·식물·섬유 32개 원천(기존 포함), 부위/획득물 80개 이상, 가공·제작 연결 20개 이상을 **검토 목표**로 삼는다. 전체 348개 잠정 원천을 즉시 활성화하지 않는다.

## 05-M 우선 원천 32
- 수목 12: 참나무, 소나무, 자작나무, 버드나무, 단풍나무, 밤나무, 개암나무, 전나무, 가문비나무, 잣나무, 달빛수(판타지), 거울수피나무(판타지).
- 풀·꽃·섬유 12: 들풀, 갈대, 부들, 아마, 쐐기풀, 대마, 클로버, 라벤더, 민들레, 담쟁이덩굴, 잠별꽃(판타지), 봄구름풀(판타지).
- 균류 및 숲 바닥 8: 느타리버섯, 표고버섯, 목이버섯, 운지버섯, 꾀꼬리버섯, 말불버섯, 솔이끼(선태류 후보), 숨결이끼(판타지).
- 상기 원천의 실제 품종·독성·생태·특수능력은 검토 전 미확정. 기존 code ID와 동일 대상이면 **새 ID 중복 금지**. 현재 resource05a:oak-log, pine-log, grass 등 실제 라이브 등록과 catalog의 단순 후보를 구분한다.

## 행동/산출 관계 계약
| 액션 | 예시 원천 | 산출물 종류 | 원천 소모/재생 |
|---|---|---|---|
| 조사 | 모든 원천 | 도감 정보 | 소모 없음 |
| 가지 채집 | 버드나무, 참나무 | 가지 | 비파괴, 별도 회복 |
| 수액·송진 채취 | 참나무, 소나무 | 수액·송진 | 별도 재충전; 벌목 수량과 독립 |
| 열매·씨앗 채집 | 밤나무, 참나무 | 열매·씨앗 | 계절별 갱신 |
| 벌목 | 벌목 가능 수목 | 통나무/목질 | 개체 소모, 장기 재생 |
| 줄기 수확 | 아마, 갈대, 쐐기풀 | 섬유 원료 | 종별 재생 |
| 꽃 채집 | 라벤더, 민들레 | 꽃/잎 | 계절별 수확 |
| 균류 채집 | 기존 05-B 균류 | 자실체 | 균사체 생태 모델 존중 |

**설계 핵심:** 한 참나무의 도토리를 수확했다고 통나무 재고가 0이 되면 안 된다. 같은 SourceEntity 아래 branch/sap/fruit/log 별도 채취 슬롯을 검토한다. 기존 resource05a 노드 및 fungi05b 상태 모델과 호환 테스트 우선.

## 4개 구현 묶음 (각각 개별 PR)
1. **05-M1: 원천/ID 감사 + 행동·산출 슬롯 계약.** master v0.5와 기존 런타임 ID 대응, 대상별 실제 출현/획득 여부, 동의어/광상과 개별 종의 차이, 수목 부산물 독립 재생/저장 모델 문서화.
2. **05-M2: 수종 확대.** 기존 참나무·소나무 보존, 자작나무·버드나무 등의 실제 등장/벌목 및 비파괴 부산물 작업 추가. 두 수종의 판재가 같은 범용 제작법을 만족하는지 확인.
3. **05-M3: 식물/섬유 확대.** 갈대·아마·쐐기풀 등 실제 수확 경로부터 실·밧줄·엮음재 가공으로 연결. 섬유 전환 불가능 종과 유독 식물의 식용 허가 금지.
4. **05-M4: 균류·판타지·회귀.** 기존 균류 생태에 겹치지 않는 새로운 산출/조사, 판타지 소재는 승인된 경우에만 활성. 실제 UI, 자동 행동, 저장/로드, 기존 05-H/I 및 05-L 제작 회귀.

## 05-N과의 경계
- 05-M에서는 자원을 **실제 채집하고 기초 가공**하게 하는 데 집중한다. 바구니·밧줄 같은 닫힌 제작 체인은 반드시 유지한다.
- 05-N에서 제작 UI 개선, 혼합재 표시, 반복 제작, 제작할 수 있는 아이템군 확대를 집중 추진한다.
- 유저 결정: 완성품에서 실제 소모한 재료 **이름/수량**은 확인 가능하게 하지만, 전 단계의 출처/채집 장소/제작 시간 등 전체 이력 추적은 만들지 않는다.
- 신성/이질 소재 여부는 관련 금기 판정에 필요한 출처 메타데이터만 정확히 기록하고 일반 몽환/공허 성질에 금기를 확대하지 않는다.

## 개발 완료 게이트
- 신규 원천마다 sourceId/서식 지역/획득 행동/산출물 ID/수량/도구/회복 조건/활용/도감 노출을 결정하고 코드 검증.
- 신규 itemDefinition에 저장 호환 및 옛 registry 공존 정책 확정.
- 적어도 2종 수목이 각기 다른 판재를 생산하고 **한 범용 레시피**에 투입되는 실제 테스트.
- 동일 원천의 비파괴 채취가 벌목 재고를 잘못 소모하지 않는지, 고갈/재생/계절 경계/저장 테스트.
- 기존 05-H/I 17개 레시피와 05-L 2개는 유지하고 엔진, Windows, Chromium 자동 검사 및 UI 검수.
