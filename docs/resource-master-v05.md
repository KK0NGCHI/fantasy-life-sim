# Somnium 자원 마스터 설계 v0.5 — 통합 원장과 제작 관계

> 2026-10-27 / **기획 자료**. 사용자 승인: 혼합형 제작(종 정체성 보존+범용 호환), 기존 v0.3/v0.4 확장 방향. **이 표의 새 종·수치·효과가 모두 세계관 확정되었다는 뜻은 아니다.** 런타임 구현은 별도.

## 포함 범위
- v0.3의 원천명/지역/판타지 여부 **256 배치**와 Git v0.4의 획득물·가공·활용이 있는 **128 배치**를 합친 **384개 배치**다.
- [마스터 원천 표](./resource-master-v05.tsv): 잠정 병합 기준(공백·광맥 접미 등)으로 **348개 잠정 원천**. sourceId는 **제안용**이며 런타임 ID가 아니다.
- [연결 관계표](./resource-edges-v05.tsv): 384개 지역별 원천 연결. v0.3의 상세 산출물 문구는 원본 문서에서 추출해 추가 이관해야 하므로 현재 **v03-details-pending-import** 표시. **미완성 필드를 완성 레시피로 간주하지 말 것.**
- [기존 v0.4 관계표](./resource-relations-v04.tsv)는 원본으로 유지한다. 동일 이름의 다른 자원, 또는 이름이 다른 같은 자원은 전문가 검토 전에 자동 병합·분리 확정 금지.

## 식별자 계층
1. `sourceId`: 종·광상·사육 원천 등. 여러 지역을 공유 가능.
2. `itemDefinitionId`: 실제 얻는 **부위/자원**별 원재료. 원천과 1:N 관계.
3. `processedDefinitionId`: 원재료 가공물. 재료군·형태를 부여하며 수종/출처 보존.
4. `recipeId`: 투입 슬롯의 정확 ID 또는 family/form/grade/traits 조건과 구조·기능·보조·장식·매개 역할 명시.
5. `itemInstance`: 제작 당시 재료·역할·기원·신성/이질 속성/품질 이력. 동일 범용 완제품 정의로 서로 다른 인스턴스 가능.

## 이중 등록 해소 규칙
- `참나무`를 여러 지역에 배치할 때 원천 하나·지역 복수, 산출물은 하나의 정의를 공유한다.
- `석영`/수정 공동·`황동석`/구리광맥 등은 **광물종과 광상**을 구분한다. 기계적 문자열 정규화로 합치지 않는다.
- `물미나리`/미나리, `갈대`/갈대, `산양`/산양 등은 자동 추정 대신 검토 라벨을 유지한다.
- 현실 식용성/유독성 검증 전 자동으로 게임 음식 레시피 허가 금지. 신성/이질적 원천 태그는 지역만으로 부여 금지.

## 검증할 실패·예외 경로
- 재료군 일치는 완성품의 실제 기능재 역할을 보장하지 않는다. role 최소 조건/가공 적합성 확인.
- 한 인스턴스를 두 입력 슬롯에 중복 할당하여 **이중 소비하지 않는다**.
- 동일 itemDefinition에 서로 다른 재료 이력의 인스턴스는 원천/속성 때문에 합치면 안 되는 경우 분리.
- 도감에만 등록된 광물은 런타임 획득·제련 가능하다고 판정하지 않는다.
- 일반 축산 범주 5, 식성 4(골렘 잡식, 이질식 사료 단일), 저장 음식 불부패, 신성/이질적 기원의 정확한 금기 조건 유지.
- 재료 부족/유효하지 않은 레시피는 0턴·0소비, 접수된 작업의 게임 내 실패는 기존 행동 규약을 따른다.

## 설계 완료 판정 전 남은 일
- **원본 v0.3의 획득물 및 사용처 세부 필드를 전체 TSV에 이관**, 현재 누락 표기 해소.
- 잠정 ID를 코드의 실제 source/item ID와 매칭·중복·동의어 감사.
- 384개 배치의 원재료 부위별 itemId와 레시피 연결을 하나씩 검증.
- 현실종의 서식/독성 검증, 판타지 종 명칭 승인, 공정 시간·성능 밸런스 승인.
- 저장 스키마 확장·마이그레이션·원자성 테스트를 기술 명세로 승인.

**위 작업 전에는 전체 콘텐츠 완성과 구현 준비 완료를 주장하지 않는다.**
